# Factory dashboard

React + TypeScript + Vite. Look and behaviour follow prototype variant E (branch `prototype/dashboard`, `?variant=E`).

```sh
npm install
npm run dev        # http://localhost:5173 — the dashboard (needs `factory server` on :47821); ?gallery for the design-system gallery (&theme=light|dark)
npm run build      # rebuilds dist/, which is committed: rebuild and commit it with every source change
npm run typecheck
npm test
```

## Design system (`src/ds`)

**Rule: the dashboard UI is built only from the design system's tokens and components. No one-off styling** — no raw colours, sizes, radii or timings, and no component-local CSS outside `src/ds`. Inside `src/ds`, colours, type, spacing, radii and motion come from `tokens.css`; a component's own fixed geometry (a 7px dot, an 18px badge) may stay literal in `components.css`. If a screen needs something the system lacks, add it to `src/ds` (token, component or variant), show it in the gallery in every state, and check it against variant E.

- `tokens.css` — colour roles written once as `light-dark(light, dark)` (dark = variant E, light derived; follows the OS unless `<html data-theme>` overrides), type scale, spacing, radii, motion. `motion.ts` mirrors the motion tokens for Framer Motion.
- Components: `MachinePill` (inert without `onToggle`) / `MachinePills`, `NeedsCount` / `DoneUnseenCount` / `HiddenNeedsBadge`, `Tag`, `StateBadge` / `StateDot` (a quiet Working session reads "Working · quiet 23m", counting up), `StateChip` (Needs you pulse + flash, glides between Phases; dimmed while its session is quiet), `FlowStrip` / `FlowCell` (cells never overflow: chips ellipsize and wrap to two lines), `Inbox` / `NeedsYouCard` / `DoneCard` / `InboxHeader` / `HiddenSessions` (under the inbox: "List N hidden sessions", each opening its detail), `NeedsDetail` (the centre's Needs you block on a waiting session: reason, where, Copy resume command), `Split` (variant E's page: the flow strip full width on top, then the inbox beside the centre, each scrolling on its own; the centre scrolls back to the top when what it shows changes), `Panel` / `SectionHeading` / `Eyebrow` / `Empty`, `PhaseTrack` / `PhaseName`, `GraphView` (one graph style for Spec DAGs, Maps with fog, to-tickets output; drawn 1:1 and scrolling sideways inside its own frame, or with `fit` shrunk to its box), `TopBar` (wraps at phone width), `NowLine` ("now: …" headline), `SessionHeader` (crumbs with the session's own controls such as Hide/Show, state — "Working · quiet Nm" once it has had no events for the server's quiet threshold, 10 min by default, `factory server --quiet-minutes` — headline, then the `StaleNote` on a Stale session and the `NeedsDetail` on a waiting one) / `Timeline` / `Detail` / `Hint` / `SkillNote` ("running skill `<name>`" on an ad hoc session) and `AdHocView` (the ad hoc detail view: state, headline, last actions; other kinds use it, titled by kind, until their own view arrives), `TicketJobView` (Ticket, stage with a "duplicate of Job N" flag, branch, worktree, PR via `Facts` / `PrLink`, a "Mark abandoned" button while active, then last actions), `StepDetail` (one Step: Phase track and time in Phase, test pulse, files touched with their edits and +/− lines (unknown when an edit’s patch couldn’t be read), commits, PR with CI checks, review findings, the agent's checklist and the struggle badge; in a Spec Job, Blocked by and, instead of a PR, its merge into the integration branch with the merge SHA) with `Review` / `StruggleTags` / `Checks` (a PR's CI checks), `SpecJobView` (as variant E: four stat tiles — integration branch, Tickets merged, final code review, Spec PR — then stage, worktree and Mark abandoned; the Ticket DAG; the merges into the integration branch with their SHAs, the final code review, and the Spec PR with its track Draft → Ready → Merged and CI checks; the Step opened from the DAG or from its flow-strip chip) built from `Stat` / `StatTiles`, `Merges` (each Ticket merged, its SHA or unknown when git didn't print one, and how many are left) and `PrTrack` (the stages reached with when the poll saw each; Closed in Merged's place), `WayfinderView` (the Map with its fog and "Fit to width" / "Actual size", beside a side column: Destination, the Needs you block, the Decision ticket worked and its questions, decisions, tickets created and closed), `ResearchView` / `ToSpecView` / `ToTicketsView` (the planning sessions: question, searches, sources and findings; the Spec outline ticked as written; the Tickets created as a graph), `SoundToggle` (the header's sound on/off button), `Clock` (the header's local time to the second, as in variant E; hidden below 1440px), `HistoryCount` / `HistoryList` (the header's History button, variant E's, with how many Jobs ended, and the ended Jobs with their outcome, each with a Replay button; History and a Replay take the centre's place, and closing them returns to the session that was open), `ReplayView` (a finished Job over time: play/pause, scrubber with event markers, each Step's `PhaseTrack` at that moment, the event list), and the unknown placeholders `Unknown` ("—"), `UnknownPhase`, `UnknownPhaseTag`, `StaleNote` ("Stale · Machine silent — <machine> last seen Nm ago").
- There is no session table (as in variant E): sessions are reached through the flow strip, the inbox and the default selection (`selection.ts`: the session opened, else a Spec Job with an active Job, else the first Needs you, else the session that changed state last).
- Pure helpers (`format.ts`, `flow.ts`, `graph.ts`, `inbox.ts`, `jobs.ts`, `replay.ts`, `specDag.ts`, `specJob.ts`, `stepDetail.ts`, `wayfinder.ts`, `planning.ts`, `sounds.ts`, `machineFilter.ts`, `selection.ts`) are unit-tested with Vitest; components with behaviour of their own (`SpecJobView`, `WayfinderView`, `SessionHeader` via `AdHocView`) have a Testing Library test beside them.
- `src/gallery` shows every component in every state with fake data. Gallery-only layout lives in `gallery.css` and still uses tokens only.

Import everything from `src/ds` (its `index.ts` also loads the CSS).
